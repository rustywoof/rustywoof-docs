		<h2 className="mt-4 mb-0 text-3xl sm:text-4xl font-bold tracking-tight">
			Why Most Scanners Feel Slow
		</h2>

		<div>
			Most secret scanners take a long list of patterns and test every single line of every file against all of them. Add more files or more patterns and the wait grows. But here is the thing. Nearly every real key starts with a fixed beginning. AWS keys start with <code>AKIA</code>, GitHub tokens start with <code>ghp_</code>, and Stripe keys start with <code>sk_live_</code>.
		</div>

		<div>
			So Rustywoof does not read everything closely. It first sweeps your files once, looking only for those known beginnings, using a method called <strong>Aho-Corasick</strong>. Think of scanning a whole library for a handful of book titles instead of reading every page. If a file has none of them, I skip it. If one shows up, I look closer. I also measure how random the text looks (this is called Shannon entropy), because real keys look messy and fake ones like <code>AKIA_EXAMPLE_TOKEN</code> don&apos;t. That keeps the false alarms down.
		</div>

It reads the exact versions you are really using from <code>Cargo.lock</code>, <code>package-lock.json</code>, <code>pnpm-lock.yaml</code>, <code>uv.lock</code> and <code>poetry.lock</code>. Then it asks <code>api.osv.dev</code>, a public list of known vulnerabilities, about all of them in one request.
